# 0001. Свой control plane через kubeadm вместо Managed Kubernetes

**Дата:** 2026-10-14

## Контекст

Yandex Cloud предлагает Managed Service for Kubernetes: мастер обслуживает облако.
Проект учебный, цель — разобраться, как Kubernetes устроен внутри.

## Решение

Кластер поднимается на обычных VM: 1 мастер и 3 воркера.
Установка — собственные Ansible-роли поверх kubeadm, не kubespray:
kubespray делает всё одной командой и скрывает, что происходит внутри.

## Последствия

- Нужно самому решать то, что Managed делает автоматически:
  балансировщик для ingress, CSI для дисков, обновления, бэкап etcd.
- Мастер один, поэтому control plane не отказоустойчив.
  В проде нужно 3 мастера или Managed Kubernetes с региональным мастером.
- Ansible в проекте оправдан: без Managed он ставит kubeadm, containerd и CNI.
