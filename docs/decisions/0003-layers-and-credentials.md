# 0003. Слои, учётные данные и передача значений между слоями

**Статус:** принято
**Дата:** 2026-10-15

## Контекст

Слой prod должен знать, что создал bootstrap: ID облака и каталога,
имя бакета и ключи к нему. При этом слои работают от разных учётных записей,
а часть значений — секреты.

## Решение

### Две «личности», два скрипта

| Слой | От чьего имени | Авторизация | Скрипт |
|---|---|---|---|
| bootstrap | Владелец организации | `YC_TOKEN` (живёт 12 часов) | `scripts/env-bootstrap.sh` |
| prod | Сервисный аккаунт `terraform` | `YC_SERVICE_ACCOUNT_KEY_FILE` | `scripts/env-prod.sh` |

Скрипты не смешиваются в одном терминале: если выставлены и `YC_TOKEN`,
и файл ключа, провайдер может взять не тот способ авторизации.

### Значения из bootstrap — через outputs и переменные окружения

`env-prod.sh` читает outputs bootstrap командой
`terraform -chdir=terraform/bootstrap output -raw <имя>`:

| Переменная окружения | Output bootstrap | Кто читает |
|---|---|---|
| `TF_VAR_cloud_id` | `cloud_id` | `var.cloud_id` |
| `TF_VAR_folder_id` | `folder_id` | `var.folder_id` |
| `TF_STATE_BUCKET` | `bucket` | Человек при `terraform init` |
| `AWS_ACCESS_KEY_ID` | `access_key` | Backend `s3` |
| `AWS_SECRET_ACCESS_KEY` | `secret_key` | Backend `s3` |
| `YC_SERVICE_ACCOUNT_KEY_FILE` | — (путь к файлу) | Провайдер `yandex` |

Переменные с префиксом `AWS_` — потому что Object Storage совместим с Amazon S3,
и backend `s3` ищет ключи под именами, принятыми у Amazon.

### Почему не генерировать terraform.tfvars

- В `tfvars` попадают только значения для блоков `variable`. Токен провайдера
  и ключи backend туда не положить, так что скрипт с `export` нужен всё равно.
- Секреты в файле лежат на диске открытым текстом; переменные окружения
  живут только в памяти терминала.

### Backend: частичная конфигурация

Внутри блока `backend` нельзя использовать переменные: backend настраивается
раньше, чем Terraform читает переменные. Поэтому в `backend.tf` нет имени бакета
и ключей; имя передаётся при инициализации:

```bash
terraform init -backend-config="bucket=$TF_STATE_BUCKET"
```

`key = "prod/terraform.tfstate"` — путь внутри бакета. Префикс `prod/` оставляет
место для state других окружений в том же бакете.

Флаги `skip_*` отключают проверки, специфичные для Amazon
(список регионов AWS, сервис STS, номер аккаунта, контрольные суммы нового формата).

## Последствия

- Перед работой нужен `source` нужного скрипта, иначе Terraform спросит
  переменные интерактивно — это сигнал, что скрипт не запущен.
- Скрипты запускаются через `source`, а не `./script.sh`: иначе переменные
  останутся в дочернем процессе. По той же причине в них нельзя использовать
  `exit` — он закроет терминал.
- Блокировки state (state locking) пока нет. Для одного человека это не критично;
  вернуться к вопросу при подключении CI.
